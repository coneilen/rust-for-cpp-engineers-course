Lesson 9 · 30 minutes

Native Threads and Channels

Give Pulsewatch a long-lived worker pool: choose scoped or spawned native threads deliberately, hand off work through mpsc channels instead of shared locked state, and shut every worker down cleanly.

By the end: You can choose between a scoped thread and a spawned 'static thread, read a move closure and a JoinHandle, choose an unbounded channel or a bounded sync_channel for backpressure, and build a worker pool whose workers never hold a lock while doing the actual work.

Part 1: scoped threads and spawned threads solve different lifetime shapes

Lessons 5 and 6 used thread::scope because the workers borrowed data owned by the enclosing function and finished before that function returned. Pulsewatch's monitoring pool is different: it is created once and outlives the function that creates it, so its threads cannot borrow anything local. That calls for thread::spawn instead.

ChoiceWhat the compiler requiresC++ bridgeUse it when
thread::scope(|s| ...)Every s.spawn(...) closure is joined before scope returns, so it may borrow local, non-'static data.Closest to a std::jthread whose destructor always joins, scoped to one block.
thread::spawn(move || ...)The closure must be 'static and Send: it may only contain owned data or data with no shorter lifetime, such as an Arc clone.Closest to a detachable std::thread whose captured state you manage manually.

A long-lived worker pool must use thread::spawn: nothing guarantees the pool's threads finish before the function that built the pool returns.

Part 2: move closures, JoinHandle, and panics

Conceptual example — illustrates move closures and JoinHandle; it is not added to the crate.

use std::sync::Arc;
use std::thread::{self, JoinHandle};

fn spawn_reporter(label: Arc<str>) -> JoinHandle<u32> {
    thread::spawn(move || {
        println!("reporter {label} starting");
        42
    })
}
SyntaxMeaning
Arc<str>An atomically reference-counted, immutable string slice; cloning it increments a count instead of copying text, and the clone is 'static-safe to move into the thread.
move ||Forces the closure to take ownership of every captured variable, here label, instead of borrowing it. Without move, the closure would try to borrow a value that does not outlive the function.
JoinHandle<u32>An owned handle to the running thread that, once joined, yields the closure's return value, here u32.
handle.join()Blocks until the thread finishes and returns Result<u32, Box<dyn Any + Send>>: Ok with the return value, or Err carrying the panic payload if the thread panicked.

A panic inside a spawned thread does not crash the process by default; it unwinds that one thread and is reported through join()'s Err variant. Code that calls handle.join().expect("...") chooses to convert that reported panic into its own panic. Pulsewatch's worker pool below chooses differently: it converts a probe's panic into an ordinary value instead of propagating it.

Part 3: choose backpressure, not just a queue

The Rust standard library ships one idea, a channel, with two behaviors. Both move ownership of each sent value from producer to consumer:

ChannelBehavior when fullC++ bridge
mpsc::channel()Unbounded. send never blocks; a producer that outruns its consumer grows memory without limit.An unbounded thread-safe queue with no flow control.
mpsc::sync_channel(n)Bounded to n buffered values. send blocks once the buffer is full until a consumer makes room: built-in backpressure.Closest to a fixed-capacity blocking queue guarded by a condition variable.

The Rust standard library documentation restates a slogan from the Go language documentation for exactly this shape of design: “Do not communicate by sharing memory; instead, share memory by communicating.” Pulsewatch's worker pool follows that: probes and results move between threads as owned values sent through channels, not as fields mutated under a lock held by multiple threads at once.

Part 4: a worker pool that never holds a lock across a probe's work

Multiple worker threads must share one queue of incoming work. A channel Receiver cannot be cloned, so the standard pattern wraps it in Arc<Mutex<Receiver<T>>>. The lock only has to protect the single act of pulling the next job; the probe itself runs after the guard is dropped.

File: crates/pulsewatch-core/src/worker_pool.rs — create.

use std::panic::{catch_unwind, AssertUnwindSafe};
use std::sync::mpsc::{self, Receiver, SyncSender};
use std::sync::{Arc, Mutex};
use std::thread::{self, JoinHandle};

use crate::{Probe, Sample};

pub type BoxedProbe = Box<dyn Probe<Output = Sample> + Send>;

pub enum WorkerEvent {
    Sampled(Sample),
    Panicked { probe_name: String },
}

pub struct WorkerPool {
    job_tx: SyncSender<BoxedProbe>,
    handles: Vec<JoinHandle<()>>,
}

impl WorkerPool {
    pub fn new(worker_count: usize, outcomes: mpsc::Sender<WorkerEvent>) -> Self {
        let (job_tx, job_rx) = mpsc::sync_channel::<BoxedProbe>(worker_count * 2);
        let job_rx = Arc::new(Mutex::new(job_rx));

        let handles = (0..worker_count)
            .map(|id| {
                let job_rx = Arc::clone(&job_rx);
                let outcomes = outcomes.clone();
                thread::Builder::new()
                    .name(format!("pulsewatch-worker-{id}"))
                    .spawn(move || worker_loop(id, job_rx, outcomes))
                    .expect("failed to spawn worker thread")
            })
            .collect();

        Self { job_tx, handles }
    }

    pub fn submit(&self, probe: BoxedProbe) {
        self.job_tx.send(probe).expect("worker pool is shut down");
    }

    pub fn shutdown(self) {
        drop(self.job_tx);
        for handle in self.handles {
            handle.join().expect("worker thread panicked unexpectedly");
        }
    }
}

fn worker_loop(
    id: usize,
    job_rx: Arc<Mutex<Receiver<BoxedProbe>>>,
    outcomes: mpsc::Sender<WorkerEvent>,
) {
    loop {
        let job = {
            let rx = job_rx.lock().expect("job queue poisoned");
            rx.recv()
        }; // the lock guard is dropped here, before any probe runs

        let mut probe = match job {
            Ok(probe) => probe,
            Err(_) => break, // every sender dropped: shut down cleanly
        };

        let probe_name = probe.name().to_string();
        let outcome = match catch_unwind(AssertUnwindSafe(|| probe.sample())) {
            Ok(sample) => WorkerEvent::Sampled(sample),
            Err(_) => {
                eprintln!("worker {id}: probe '{probe_name}' panicked during sample()");
                WorkerEvent::Panicked { probe_name }
            }
        };

        if outcomes.send(outcome).is_err() {
            break; // the collector has gone away; nothing left to report to
        }
    }
}
New lineWhy it exists
let job = { let rx = ...lock()...; rx.recv() };The block expression ends before probe.sample() runs, so the MutexGuard is dropped immediately after recv() returns. No worker holds the queue lock while sampling.
Err(_) => breakrecv() returns Err only once every SyncSender clone has been dropped and the queue is empty. That is the pool's shutdown signal, not an error to report.
catch_unwind(AssertUnwindSafe(|| probe.sample()))Converts a panic inside sample() into Err instead of unwinding the whole worker thread. AssertUnwindSafe is required because a &mut borrow is not automatically considered safe to resume after a caught unwind; here it is safe because probe is discarded either way.
WorkerPool::shutdown(self)Takes self by value, drops the sender first so workers can observe the closed channel, then joins every handle. The pool cannot be used again after this call, which the type system enforces by consuming it.
🧭
Stability and production boundary

thread::scope, thread::spawn, mpsc::channel, mpsc::sync_channel, and catch_unwind are all stable. One shared Mutex-guarded Receiver is a common, well-understood pattern, but every worker still contends on that single lock to fetch its next job; at very high job-submission rates a per-worker channel or a work-stealing scheduler can scale better. catch_unwind also only stops unwinding panics from crossing a thread boundary — it does not recover from a process abort, and code compiled with panic = "abort" cannot unwind at all.

Knowledge check

1. Why must WorkerPool::new use thread::spawn rather than thread::scope?

Answer: The pool is meant to outlive the function that creates it. thread::scope requires every spawned worker to be joined before the scope ends, which would defeat a long-lived pool; thread::spawn instead requires 'static, owned captures.

2. What does choosing mpsc::sync_channel(n) over mpsc::channel() change about submit?

Answer: Once n jobs are queued, submit's send call blocks until a worker consumes one, applying backpressure. With an unbounded channel, submit never blocks and a fast producer can queue unbounded memory.

3. Why is the MutexGuard from job_rx.lock() dropped before probe.sample() runs?

Answer: The guard is scoped to a block expression that ends right after recv(). Holding the queue lock during the probe's work would force every other worker to wait for one probe to finish, serializing the entire pool.

4. What does Err(_) => break in worker_loop actually detect?

Answer: That every SyncSender clone for the job channel has been dropped and no more jobs remain, which is exactly the signal WorkerPool::shutdown produces by dropping job_tx before joining the workers.

Recap and decision rules

Workers finish before this function returns? thread::scope; may borrow local data
Workers outlive this function?               thread::spawn; captures must be 'static + Send
Producer must never block?                   mpsc::channel() (unbounded)
Producer should be slowed by a slow consumer? mpsc::sync_channel(n) (bounded backpressure)
Sharing one Receiver across workers?          Arc<Mutex<Receiver<T>>>; lock only around recv()
A job might panic?                            catch_unwind + AssertUnwindSafe; report, don't crash
Pool should stop accepting and drain cleanly? Drop the sender, then join every handle
