Control Flow, Functions, Closures, and Macros

Make decisions with if/match, loop deliberately, write functions where the tail expression is the return value, capture your environment with closures, and understand what println! and friends actually are. Finish by rendering real greetings by style in rust-greeter.

Part 1: if and match as expressions

if in Rust produces a value, so it can appear directly on the right-hand side of a let — but every arm must produce the same type, unlike C++'s ternary operator which quietly permits mismatched types via conversion:

let label = if count > 1 { "greetings" } else { "greeting" }; // both arms: &str

match generalizes this to any number of patterns and is exhaustive: the compiler rejects code that does not cover every possibility, which is what made lookup_style's trailing _ => None mandatory in Lesson 3. Patterns can also destructure and add guards — extra if conditions evaluated only when the pattern itself matches:

fn name_length_label(name: &str) -> &'static str {
    match name.len() {
        n if n == 0 => "empty",
        n if n <= 4 => "short",
        n if n <= 12 => "medium",
        _ => "long",
    }
}

Each arm above is a guard (if n == 0, if n <= 4, …) attached to the same binding pattern n; the first guard that evaluates true wins, and the final _ still must be present to keep the match exhaustive even though the guards look like they cover everything.

Part 2: loop, while, for, and break with a value

LoopWhen to use it
loop { ... }Unconditional repetition; the only loop form that can break with a value, replacing a hand-written retry loop
while condition { ... }Repeat while a condition holds — same shape as C++'s while
for item in iterable { ... }Iterate a range or collection directly; the idiomatic default, since it cannot skip a bound or forget to increment

Illustrative excerpt — not added to rust-greeter. A manual countdown with while works, but a for loop over a range says the same thing with no mutable counter to get wrong:

Works, but a manual counter
let mut remaining = 3u8;
while remaining > 0 {
    println!("tick {remaining}");
    remaining -= 1;
}
Idiomatic: no counter to maintain
for remaining in (1..=3).rev() {
    println!("tick {remaining}");
}

1..=3 is an inclusive range (1 through 3); 1..3 would be exclusive of 3. loop is the only loop that can hand back a value through break, which while/for cannot do:

fn first_space_index(name: &str) -> Option<usize> {
    let mut chars = name.char_indices();
    loop {
        match chars.next() {
            Some((index, ' ')) => break Some(index), // break WITH a value
            Some(_) => continue,
            None => break None,
        }
    }
}

Some((index, ' ')) destructures the tuple char_indices() yields, matching only when the character itself is a space, and binding index at the same time — pattern matching and destructuring in one step.

Part 3: functions — statements, expressions, and returns

A block's final line, if it has no trailing semicolon, is the block's value — the same rule that makes if/match usable as expressions applies to whole function bodies:

fn shout_line(text: &str, should_shout: bool) -> String {
    if text.is_empty() {
        return String::new(); // early return — still needs `return` and `;` here
    }
    if should_shout {
        text.to_uppercase() // tail expression, no semicolon: this IS the return value
    } else {
        text.to_string() // tail expression in the other arm
    }
}
C++ instinctRust reality
Every path needs an explicit returnThe final expression of a block (no semicolon) is implicitly returned; return is only needed to exit early
A semicolon is just a statement terminatorAdding a semicolon turns an expression into a statement that evaluates to () — text.to_uppercase(); as the last line would make the function return (), a type error against -> String

Generics are previewed only briefly here — Lesson 6 covers them properly alongside traits and lifetimes. The rule for this lesson: reach for a generic function only when a concrete type genuinely does not fit; everything in rust-greeter so far has a concrete, known type at every call site, so none of today's functions need one.

Part 4: closures and capture modes

A closure is an anonymous function that can capture variables from its surrounding scope — C++'s lambda, with the same trailing-brace call syntax but different capture rules. Without move, the compiler does not simply borrow everything: it infers the least restrictive capture each variable actually needs from how the closure body uses it — an immutable borrow if the body only reads the variable, a mutable borrow if the body mutates it, or a move if the body must consume/own it outright. The closure below only reads label, so the compiler captures it by immutable borrow:

let label = "casual";
let describe = |name: &str| format!("{name} ({label})"); // captured by immutable borrow (read-only use)
println!("{}", describe("Ada"));
println!("{label}"); // still usable — `describe` only borrowed it

Mutating a captured variable inside the closure body makes the compiler infer a mutable borrow instead — still not a move, so the original binding is usable again once the closure's last use ends:

let mut count = 0;
let mut increment = || count += 1; // captured by mutable borrow (the body mutates `count`)
increment();
increment();
// `increment`'s last use is above, so its mutable borrow of `count` has ended here
println!("{count}"); // 2 — `count` is usable again

The move keyword forces a closure to capture everything it uses by value instead of letting the compiler infer a borrow. It is commonly needed when a closure must own captured non-'static locals—for example, when handing work to a thread that may outlive the current scope (Lesson 9 uses this pattern for real). A noncapturing closure, or one that only refers to static data, can outlive its creating scope without move. What happens to an original captured binding depends on whether its type is Copy: a Copy value (like the u8 below) is copied into the closure, so the original stays usable too; a non-Copy value (like a String) is moved in, so the original binding is gone:

let n: u8 = 5; // Copy
let show_n = move || println!("n inside closure = {n}");
show_n();
println!("n outside closure = {n}"); // still usable — `u8` is `Copy`, so `move` copied it

let label = String::from("casual"); // not Copy
let describe = move |name: &str| format!("{name} ({label})"); // takes ownership of `label`
println!("{}", describe("Ada"));
// println!("{label}"); // would not compile: `label` was moved into `describe`
TraitWhat it means for a closure
FnOnceCan be called at least once; may consume captured values
FnMutCan be called multiple times; may mutate captured values
FnCan be called multiple times; only reads captured values

This lesson only reads closures used inline, such as inside .map(...) below; Lesson 6 covers writing functions that accept a closure as a parameter using these three traits explicitly.

Part 5: macros — what println! actually is

The trailing ! is not decoration: println!, vec!, and format! are all macros, expanded into ordinary code by the compiler before type-checking runs — they are not regular functions, and that is precisely why they can accept a variable number of arguments and check format-string placeholders at compile time, something no plain Rust function can do.

MacroWhat it produces
println!("{name}")Prints to stdout with a trailing newline; expands into code that validates {name} against an actual variable named name at compile time
format!("{name}")Same formatting, returned as an owned String instead of printed
vec![1, 2, 3]Builds a Vec<i32> without manually calling Vec::new() then .push(...) three times

You can define your own declarative macro with macro_rules!, matching on the shape of the tokens passed in — this is pattern matching over syntax, not values:

macro_rules! greet_many {
    ($name:expr, $times:expr) => {{
        let mut lines = Vec::new();
        for _ in 0..$times {
            lines.push(greeting($name));
        }
        lines
    }};
}

$name:expr and $times:expr declare that this macro accepts two comma-separated expressions; the double braces {{ ... }} are an ordinary block expression (outer braces are the macro arm's body, inner braces make that body a single block that evaluates to lines).

Rust also has procedural macros — #[derive(Debug)] from Lesson 3 is one — which run arbitrary code to generate new tokens instead of matching a fixed pattern; writing one is out of scope for this course, but recognizing #[derive(...)] and attribute macros like #[tokio::main] (Lesson 12) as macros, not built-in syntax, matters for reading real Rust code.

🛑
When not to reach for macro_rules!

If a plain function or generic function expresses the idea, prefer it: macros are harder to read, harder to debug (errors point at the expansion, not your call site), and cannot be documented with normal doc comments as clearly. greet_many! above exists to teach the mechanism; in real code, a plain function taking a count would usually be simpler and just as fast.

const TEAM_ROSTER: [&str; 2] = ["Ada Lovelace", "Grace Hopper"];

fn first_space_index(name: &str) -> Option<usize> {
    let mut chars = name.char_indices();
    loop {
        match chars.next() {
            Some((index, ' ')) => break Some(index),
            Some(_) => continue,
            None => break None,
        }
    }
}

fn shout_line(text: &str, should_shout: bool) -> String {
    if text.is_empty() {
        return String::new();
    }
    if should_shout {
        text.to_uppercase()
    } else {
        text.to_string()
    }
}

fn name_length_label(name: &str) -> &'static str {
    match name.len() {
        n if n == 0 => "empty",
        n if n <= 4 => "short",
        n if n <= 12 => "medium",
        _ => "long",
    }
}

fn render_greetings(config: &GreeterConfig) -> Vec<String> {
    let should_shout = config.style == GreetingStyle::Formal;
    let render_one = |name: &str| shout_line(&greeting(name), should_shout);

    match config.audience {
        Audience::Individual => vec![render_one(config.name())],
        Audience::Team => TEAM_ROSTER
            .iter()
            .map(|member| render_one(member))
            .collect(),
    }
}

macro_rules! greet_many {
    ($name:expr, $times:expr) => {{
        let mut lines = Vec::new();
        for _ in 0..$times {
            lines.push(greeting($name));
        }
        lines
    }};
}

File: src/main.rs — replace fn main from Lesson 3 with:

fn main() {
    let args = Args::parse();
    let audience = if args.name.contains(' ') || first_space_index(&args.name).is_some() {
        Audience::Team
    } else {
        Audience::Individual
    };

    let mut config = GreeterConfig::new(args.name.clone(), audience, args.style, args.count);
    println!(
        "{APP_NAME} config -> {} [{}]",
        config.describe(),
        name_length_label(config.name())
    );
    println!(
        "cast demo: {}; compile-time clamped default: {CLAMPED_DEFAULT}",
        describe_cast(1000)
    );
    println!("lookup_style(\"formal\") -> {:?}", lookup_style("formal"));

    for line in render_greetings(&config) {
        println!("{line}");
    }

    config.set_style(GreetingStyle::Formal);
    let repeats = config.repeats.get();
    let owned_name = config.into_name();
    for line in greet_many!(&owned_name, repeats) {
        println!("(macro) {line}");
    }
}
LineWhy it is written this way
|name: &str| shout_line(&greeting(name), should_shout)A non-move closure that borrows should_shout (a bool, Copy, from the enclosing render_greetings) — no ownership transfer needed since it never outlives that function call.
TEAM_ROSTER.iter().map(|member| render_one(member)).collect()Applies the closure to every roster entry and collects the results into a Vec<String>, matching the Vec<String> the Individual arm produces — required so match's arms agree on type.
greet_many!(&owned_name, repeats)Invokes the declarative macro from Part 5 with the owned_name obtained by consuming config through into_name, exactly as in Lesson 3.
describe_cast(1000), CLAMPED_DEFAULT, lookup_style("formal")Carried forward from Lessons 2–3 and printed here so they stay exercised — keeping the whole file warning-free under cargo build, the same standard every lesson in this course holds itself to.

Knowledge check

1. Why must both arms of let label = if count > 1 { "greetings" } else { "greeting" }; produce the same type?

Answer: if is an expression whose value is assigned to label; the compiler must know label's single type at compile time, so every arm supplying that value has to agree — unlike C++'s ternary operator, which permits differing types via conversion.

2. In first_space_index, why is loop used instead of while or for?

Answer: Only loop can break with a value (here, Some(index) or None) that becomes the loop's own value. while and for always evaluate to (), so they cannot hand back a result this way.

3. What is the difference between a closure that borrows label and one written with move, and does move always make the original binding unusable?

Answer: Without move, the compiler infers the least restrictive capture the closure body needs—an immutable borrow, a mutable borrow, or a value capture—so a borrowing closure typically leaves the original binding usable. A move closure captures by value, but a Copy value is copied in while a non-Copy value is moved. Use move when the closure needs to own captured non-'static locals, as commonly happens with spawned threads; noncapturing closures and closures using only static data do not need it merely because they outlive the current scope.

4. Why is println! a macro rather than an ordinary function?

Answer: Macros expand before type-checking, which lets println! accept a variable number of differently typed arguments and validate each { } placeholder against a real variable at compile time — something an ordinary Rust function, which has a fixed parameter list and type signature, cannot do.

5. Why does greet_many!(&owned_name, repeats) in the exercise never print an uppercase greeting?

Answer: The macro calls the original Lesson 1 greeting function directly, not shout_line or render_greetings; style-based shouting is only applied inside render_greetings, so the macro's output is unaffected by config.style.

Recap and decision rules

Value chosen from two branches?          `if` as an expression (both arms same type)
Need to cover every case of an enum?     `match` (exhaustive; add guards for extra conditions)
Repeat while a condition holds?           `while`
Repeat over a range/collection?           `for` (default choice; nothing to increment by hand)
Need to `break` out with a computed value? `loop`
Last line of a function, no semicolon?    That expression IS the return value
Need to exit a function before the end?   `return` with an explicit semicolon
Need a small function that reads/mutates context? A closure — the compiler infers borrow (immutable or mutable) or value capture from how the body uses it
Closure must own captured local data?     `move` closure — `Copy` captures are copied; non-`Copy` captures move
Formatting text or printing it?           `format!`/`println!` — macros, not functions
Matching your own repeated code shape?    `macro_rules!` only if a plain function can't say it as clearly

You now read if/match as value-producing expressions, chose loops by what they need to do rather than habit, told statements from expressions in function bodies, distinguished borrowing closures from move closures, and recognized macros as compile-time code generation.
