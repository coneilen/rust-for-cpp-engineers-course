Part 1: "smart pointer" is not one hierarchy

C++ tends to group unique_ptr, shared_ptr, and weak_ptr together as one family with one mental model. Rust's pointer types state different, incompatible invariants, and picking the wrong one is a design error the compiler will not always catch for you:

TypeOwnership and mutation invariantC++ bridgeThreads?
Box<T>Exactly one owner of a heap-allocated T.std::unique_ptr<T>If T is safe to send
Rc<T>Shared ownership on one thread; a non-atomic strong count.A shared_ptr-like handle restricted to one threadNo
Weak<T>Observes an Rc/Arc value without owning it or keeping it alive.std::weak_ptr<T>Matches whichever of Rc/Arc it observes
Arc<T>Shared ownership using an atomically updated strong count.std::shared_ptr<T> with an atomic control blockOnly if T is thread-safe
Cow<'a, T>Borrows until a mutation is needed, then clones into an owned value.No direct equivalent; closer to a string_view that can promote itself to std::string on demandIf T is safe to send

Rc and Arc look similar and are not interchangeable: Rc's reference count is a plain integer update, so Rc<T> is neither Send nor Sync. Arc pays for an atomic increment on every clone so that sharing the ownership count itself is safe across threads.

Part 2: cycles are a logical leak, not a memory-safety hole

A parent that strongly owns its children, where each child also strongly owns its parent, never reaches a strong count of zero. Nothing in that cycle is ever freed. This is a resource leak, not undefined behavior, but it is still a real production bug. Pulsewatch groups alerts into a tree; each group needs to reach its parent without keeping it alive:

File: crates/pulsewatch-core/src/alert_group.rs — create.

use std::cell::RefCell;
use std::rc::{Rc, Weak};

pub struct AlertGroup {
    pub name: String,
    parent: RefCell<Weak<AlertGroup>>,
    children: RefCell<Vec<Rc<AlertGroup>>>,
}

impl AlertGroup {
    pub fn new(name: impl Into<String>) -> Rc<Self> {
        Rc::new(Self {
            name: name.into(),
            parent: RefCell::new(Weak::new()),
            children: RefCell::new(Vec::new()),
        })
    }

    pub fn add_child(parent: &Rc<Self>, child: Rc<Self>) {
        *child.parent.borrow_mut() = Rc::downgrade(parent);
        parent.children.borrow_mut().push(child);
    }

    pub fn parent(&self) -> Option<Rc<Self>> {
        self.parent.borrow().upgrade()
    }
}
New syntaxWhy it exists
RefCell<Weak<AlertGroup>>The parent link must be replaceable after construction, so it needs interior mutability; the link itself is a non-owning Weak.
Rc::downgrade(parent)Creates a Weak observer from an existing Rc without incrementing the strong count.
self.parent.borrow().upgrade()upgrade() tries to produce a strong Rc and returns Option::None if every strong owner has already been dropped.

Every group keeps its children alive strongly through Vec<Rc<AlertGroup>>. Every child observes its parent weakly. Dropping the top-level Rc now actually frees the tree instead of leaking it.

Part 3: interior mutability means checked mutation through a shared reference

Cell<T> and RefCell<T> let a method that only borrows &self still mutate a field. Neither is thread-safe; both are single-threaded tools layered over one core primitive:

TypeRule enforcedC++ bridge
Cell<T>Whole-value get/set/replace for small, usually Copy values; never hands out a reference into the value.No direct equivalent; closer to an atomic-free, single-threaded value slot.
RefCell<T>Runtime-checked borrowing: many shared borrows, or exactly one exclusive borrow, never both at once. Violating this panics instead of compiling.The single-threaded analogue of a checked lock: no compile-time enforcement, but a checked runtime rule instead of silent aliasing.
UnsafeCell<T>The primitive that makes interior mutation possible at all. It carries no rule of its own; Cell, RefCell, and every synchronization type are built on top of it.Closest to the raw mutable keyword's effect, without any policy attached.

Pulsewatch uses Cell for a lightweight per-probe hit counter that many holders of a shared reference can update:

File: crates/pulsewatch-core/src/hit_counter.rs — create.

use std::cell::Cell;

pub struct HitCounter {
    hits: Cell<u32>,
}

impl HitCounter {
    pub fn new() -> Self {
        Self { hits: Cell::new(0) }
    }

    pub fn record(&self) {
        self.hits.set(self.hits.get() + 1);
    }

    pub fn total(&self) -> u32 {
        self.hits.get()
    }
}

record only borrows &self, yet it mutates hits. That is interior mutability: the exterior borrow is shared, the interior state still changes.

RefCell is for values too large or too structured to copy in and out on every access, such as AlertGroup's children list above. Its runtime rule can be violated, and violating it panics rather than compiling:

Conceptual example — not part of the pulsewatch-core crate. It is a standalone illustration; the Active exercise below shows how to observe the same panic inside the CLI.

Panics: already borrowed
use std::cell::RefCell;

let values = RefCell::new(vec![Millis::new(4)]);
let _read_guard = values.borrow();
values.borrow_mut().push(Millis::new(9));
// panics: already borrowed: BorrowMutError
Scope each borrow to one statement
use std::cell::RefCell;

let values = RefCell::new(vec![Millis::new(4)]);
{
    let read_guard = values.borrow();
    println!("first: {:?}", read_guard.first());
}
values.borrow_mut().push(Millis::new(9));

The left block keeps _read_guard alive while requesting an exclusive borrow on the next line; RefCell catches that at runtime instead of allowing the aliasing violation. The same discipline applies inside AlertGroup::add_child: each borrow_mut() call is a single, short-lived statement.

Not every borrowed string needs an owned copy. Cow<'a, str> ("clone on write") borrows when possible and only allocates when a value must actually change:

File: crates/pulsewatch-core/src/label.rs — create.

use std::borrow::Cow;

pub fn normalize_label(label: &str) -> Cow<'_, str> {
    if label.chars().all(|c| c.is_ascii_lowercase() || c == '-') {
        Cow::Borrowed(label)
    } else {
        Cow::Owned(label.to_ascii_lowercase().replace(' ', "-"))
    }
}

A label already written as cpu-load costs nothing extra; a label like "CPU Load" allocates exactly once to produce the normalized owned version.

Part 4: one minimal, audited unsafe boundary

Pulsewatch occasionally ingests a byte buffer handed over by a legacy native probe as a raw pointer and length. The safe wrapper accepts that shape only at this one edge, checks everything it can, and never invents ownership over memory it does not control:

File: crates/pulsewatch-core/src/unsafe_probe.rs — create.

#[derive(Debug, PartialEq, Eq)]
pub enum BufferError {
    NullWithData,
}

/// # Safety
/// For a nonzero `len`, `ptr` must point to `len` initialized, readable
/// bytes for the duration of this call. This function does not take
/// ownership of, or free, the pointed-to memory.
pub unsafe fn copy_probe_bytes(ptr: *const u8, len: usize) -> Result<Vec<u8>, BufferError> {
    if len == 0 {
        return Ok(Vec::new());
    }
    if ptr.is_null() {
        return Err(BufferError::NullWithData);
    }
    // SAFETY: `len` is nonzero, `ptr` was just checked non-null, and the
    // caller's documented contract guarantees `len` readable initialized bytes.
    let view = unsafe { std::slice::from_raw_parts(ptr, len) };
    Ok(view.to_vec())
}
New syntaxMeaning for a C++ programmer
*const u8A raw pointer: it may be null, may dangle, and is never automatically dereferenced. Closest to a bare const unsigned char* with no attached lifetime.
/// # SafetyA documentation convention, not a compiler-checked contract: it states the obligations a caller of an unsafe fn must uphold.
pub unsafe fn ...Marks the function itself as carrying unchecked preconditions. In current Rust editions, the function body still must wrap any actual unsafe operation in its own unsafe { ... } block.
std::slice::from_raw_partsBuilds a borrowed view over raw memory with no validation. Every precondition — non-null, aligned, readable, initialized, and not concurrently mutated — is the caller's responsibility.
view.to_vec()Copies the bytes into an owned, safe Vec<u8> immediately, so nothing downstream needs to reason about raw-pointer lifetime rules.

Stability and production boundary

Every container in Parts 1–3 is stable Rust. Miri is a dynamic interpreter, normally run through a nightly toolchain component, that can detect many classes of undefined behavior on the exact paths a test exercises. It is not a proof that unsafe code is correct: a path Miri never executes is a path it never checked. Raw-pointer preconditions remain the caller's obligation regardless of how many tests currently pass.

Knowledge check

1. Why can Rc<T> not be sent to a worker thread the way Arc<T> can?

Answer: Rc's strong count is a plain, non-atomic update, so Rc<T> is neither Send nor Sync. Arc pays for an atomic count specifically so sharing ownership across threads is safe.

2. In the AlertGroup tree, which link is Weak, and why does that matter?

Answer: The child-to-parent link is Weak. Because it does not add to the parent's strong count, dropping the parent's last strong owner actually frees it instead of leaving a cycle that never reaches zero.

3. What does a RefCell do when its borrowing rule is violated, and how does that differ from a compile-time borrow error?

Answer: It panics at runtime with a BorrowError or BorrowMutError. The compiler cannot catch this ahead of time because RefCell intentionally defers the check to when the borrows actually happen.

4. Does passing Miri's test suite prove copy_probe_bytes has no undefined behavior?

Answer: No. Miri is a dynamic interpreter: it can catch many undefined-behavior classes on paths a test actually exercises, but it says nothing about inputs or call patterns no test in the suite ever runs.

Recap and decision rules

One heap owner?                      Box<T>
Shared ownership, one thread?        Rc<T>; back-edge in a tree? Weak<T>
Shared ownership across threads?     Arc<T> (the inner T still must itself be thread-safe)
Usually borrowed, rarely changed?    Cow<'a, T>
Small Copy value, mutated via &self? Cell<T>
Larger value, mutated via &self?     RefCell<T>, one short-lived borrow at a time
Building new interior mutability?    UnsafeCell<T> plus a proven, written rule on top
Touching a raw pointer?              One small unsafe fn, one written Safety section, one safe return type
