🦀 22-lesson course · 11 hours

Learning Rust for C++ Engineers

Transfer your C++ instincts to Rust, then build, test, debug, profile, and integrate a concurrent networked monitoring system from first principles.

The finish line

By the end of this course, you will be able to:

  • Model data and control flow with Rust's value, type, struct, enum, and function fundamentals instead of reaching for C++ habits.
  • Use ownership, borrowing, traits, lifetimes, and explicit errors to design Rust APIs from scratch.
  • Build native-threaded and Tokio-based programs with bounded work, deliberate synchronization, networking, HTTP, and SQLite persistence.
  • Test, debug, observe, benchmark, and dynamically check unsafe boundaries using the appropriate Rust tools.
  • Migrate a real C++ module in stages and choose a justified C ABI, C++ bridge, JNI, UniFFI Kotlin, or UniFFI Swift boundary.
🧭
Scope and prerequisites

You should recognize C++ functions, classes or structs, references, RAII, threads, and basic build concepts. Before starting, install stable Rust with rustup, rust-analyzer, Clippy, rustfmt, and one debugger (rust-lldb or rust-gdb). To avoid setup delays later, preinstall a nightly toolchain with Miri and the platform dependencies required by cargo-flamegraph. Nightly Miri, sanitizers, and profiling are optional tools used in Lessons 8 and 18; the main course code targets stable Rust.

⚠️
Deliberate boundaries

This course teaches a production-shaped learning system, not a production certification. It does not promise mechanical C++ conversion, universal interop coverage, formal proof of unsafe code, platform signing, GUI development, or deployment-specific security hardening. Each migration and foreign-function boundary still requires project-specific ownership, ABI, threat-model, and rollout review.

How to follow the hands-on steps

  • Lessons 1–6: work in the rust-greeter/ package created in Lesson 1.
  • Lessons 7–22: work in the pulsewatch/ workspace created in Lesson 7 and carry each completed lesson forward.
  • path/to/rust-greeter and path/to/pulsewatch mean the location where you created or checked out the project. Do not create a literal folder named path/to.
  • Each code listing identifies its exact file and whether to create, replace, append, or only read the excerpt. Commands state the directory they run from and the result you should see.
  • When a lesson says excerpt, do not replace the entire file with that block; insert it at the named location or use it only to study the concept.
